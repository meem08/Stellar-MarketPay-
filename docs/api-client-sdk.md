# API Client SDK

Stellar MarketPay ships a first-party, typed TypeScript client SDK from this repository. SDKs for other languages are planned (see [Roadmap](#roadmap)).

## Available SDKs

| Language   | Package                                  | Status                              | Documentation                      |
| ---------- | ---------------------------------------- | ----------------------------------- | ---------------------------------- |
| TypeScript | `@stellar-marketpay/client`              | ✅ Published from `packages/client` | [TypeScript Docs](#typescript-sdk) |
| Python     | `stellar-marketpay`                      | 🚧 Planned — not yet published      | —                                  |
| Go         | `github.com/stellar-marketpay/go-client` | 🚧 Planned — not yet published      | —                                  |

> Looking for the auto-generated codegen output? The legacy generated clients (`sdk/typescript`, `sdk/python`, `sdk/go`) are produced from `backend/docs/openapi.json` — see [SDK Generation](#sdk-generation).

## Quick Start (TypeScript)

```bash
npm install @stellar-marketpay/client
```

```typescript
import { StellarMarketPayClient } from "@stellar-marketpay/client";

const client = new StellarMarketPayClient({
  baseURL: "https://api.stellarmarketpay.com", // default
});

// List jobs (public endpoint — no token required)
const jobs = await client.jobs.list({
  category: "development",
  limit: 20,
});

console.log(jobs.data); // Job[]

// Create a job (requires authentication)
const newJob = await client.jobs.create({
  title: "Build a website",
  description: "Need a responsive Next.js website",
  budget: 500,
  clientId: "GXXXXXX...",
  category: "development",
  skills: ["React", "Next.js", "TailwindCSS"],
});

console.log("Job created:", newJob.data.id);
```

## TypeScript SDK

The SDK lives in [`packages/client`](../packages/client) and is published as `@stellar-marketpay/client`. It is dependency-free (built on the global `fetch` API), ships ESM + CommonJS builds with bundled type declarations, and derives its types from the OpenAPI specification generated by `backend/scripts/generate-openapi.js`.

### Installation

```bash
npm install @stellar-marketpay/client
# or
yarn add @stellar-marketpay/client
# or
pnpm add @stellar-marketpay/client
```

Requires Node.js ≥ 18 (or any runtime with `fetch`).

### Configuration

```typescript
import { StellarMarketPayClient } from "@stellar-marketpay/client";

const client = new StellarMarketPayClient({
  baseURL: "https://api.stellarmarketpay.com", // default
  timeout: 10000, // request timeout in ms (default: 30000)
  headers: { "X-Custom-Header": "value" }, // extra headers on every request
  token: "your_jwt_token", // optional initial access token
  refreshToken: "refresh_token", // optional — for Node where cookies are absent
  csrfToken: "csrf_token", // optional — for cookie-authenticated browsers
  credentials: "include", // fetch credentials mode (use "include" for cookies)
  autoRefresh: true, // refresh + retry once on 401 (default: true)
  onTokenRefresh: ({ token }) => console.log("token refreshed"),
  fetch: customFetch, // optional custom fetch implementation
});
```

A convenience factory is also exported: `createClient(config)`.

### Authentication (SEP-10)

```typescript
// 1. Get a challenge transaction to sign with the user's Stellar wallet
const { transaction } = await client.auth.getChallenge({
  account: "GXXXXXX...",
});

// 2. Sign with Freighter (in browser)
const signedXdr = await window.freighterApi.signTransaction(transaction);

// 3. Verify and get a JWT — the token is stored on the client automatically
const { token, csrfToken } = await client.auth.authenticate({
  transaction: signedXdr,
});
```

Subsequent requests carry `Authorization: Bearer <token>` automatically. If a request fails with `401`, the SDK refreshes the access token (via `POST /api/auth/refresh`) and retries the request once. Additional auth helpers:

```typescript
client.setToken("jwt"); // replace the access token (e.g. from storage)
client.setRefreshToken("refresh_token"); // Node/server usage where cookies are absent
client.setCsrfToken("csrf_token"); // cookie-authenticated browser requests (X-CSRF-Token header)

await client.auth.refresh(); // explicit refresh — throws StellarMarketPayError on failure
await client.auth.getCsrfToken(); // fetch a CSRF token (GET /api/auth/csrf-token)
await client.auth.logout(); // revoke the refresh token (POST /api/auth/logout)
```

### Jobs

```typescript
// List jobs with filters and cursor pagination
const jobs = await client.jobs.list({
  category: "development",
  status: "open",
  limit: 20,
  cursor: "eyJpZCI6...",
});

// Get a specific job (optionally as a specific viewer)
const job = await client.jobs.get("job-id-123", "GXXXXXX...");

// Create a job (requires authentication)
const newJob = await client.jobs.create({
  title: "Build a DeFi dashboard",
  description: "Need a React dashboard for Stellar DeFi analytics",
  budget: 1000,
  clientId: "GXXXXXX...",
  category: "development",
  skills: ["React", "TypeScript", "Stellar SDK"],
  visibility: "public",
});

// Update a job (requires authentication)
const updatedJob = await client.jobs.update("job-id-123", {
  status: "in_progress",
});

// Delete a job (requires authentication)
await client.jobs.delete("job-id-123");
```

### Applications

```typescript
// Get applications for a job (cursor paginated)
const applications = await client.applications.listByJob("job-id-123", {
  limit: 10,
});

// Submit an application
const application = await client.applications.create({
  jobId: "job-id-123",
  freelancerId: "GXXXXXX...",
  proposal: "I have 5 years of experience with React and Stellar...",
  bidAmount: 800,
  estimatedDuration: "2 weeks",
});

// Accept an application (as the job's client)
await client.applications.accept("application-id-123", {
  clientAddress: "GXXXXXX...",
  contractTxHash: "optional-tx-hash",
});

// Withdraw an application (as the freelancer)
await client.applications.withdraw("application-id-123", {
  freelancerAddress: "GXXXXXX...",
});
```

### Escrow

```typescript
// Fund an escrow
await client.escrow.create({ amount: 1000 });

// Fetch the escrow record for a job
const { data: escrow } = await client.escrow.get("job-id-123");

// Release escrow to the freelancer — the caller's identity comes from the JWT
const release = await client.escrow.release("job-id-123", {
  contractTxHash: "optional-tx-hash",
});
console.log(release.referralBonus); // optional referral payout payload
console.log(release.autoConversion); // optional XLM→USDC conversion payload
```

### Error Handling

Every non-2xx response throws a typed `StellarMarketPayError`:

```typescript
import {
  StellarMarketPayError,
  isStellarMarketPayError,
} from "@stellar-marketpay/client";

try {
  const job = await client.jobs.get("invalid-id");
} catch (error) {
  if (isStellarMarketPayError(error)) {
    console.error("API Error:", error.message); // normalised from either error shape
    console.error("Status Code:", error.statusCode);
    console.error("Code:", error.code); // machine-readable code when supplied
    console.error("Response:", error.response); // raw parsed body
  } else {
    console.error("Unexpected error:", error);
  }
}
```

### TypeScript Types

All SDK methods are fully typed, and the core types are derived from the OpenAPI spec (`src/schema.ts`, regenerated via `npm run generate`):

```typescript
import type {
  Job,
  Application,
  Escrow,
  JobCreateParams,
  JobListParams,
  PaginatedResponse,
  ApiResponse,
} from "@stellar-marketpay/client";

const jobs: PaginatedResponse<Job> = await client.jobs.list({
  limit: 20,
});

jobs.data.forEach((job: Job) => {
  console.log(job.title, job.budget);
});
```

The full generated OpenAPI types (`paths`, `components`, …) are also re-exported from the package root.

## Roadmap

Python and Go SDKs are planned but **not yet published**. Until they ship, use the REST API directly or the TypeScript SDK above; see [SDK Generation](#sdk-generation) for the legacy codegen output.

## SDK Generation

The auto-generated clients are produced from the OpenAPI specification (`backend/docs/openapi.json`), which is itself generated from route-level `@swagger` annotations.

### Frontend Typed Client & OpenAPI Types

The frontend uses `openapi-typescript` to generate end-to-end typed definitions directly from `backend/docs/openapi.json`:

```bash
# 1. Regenerate backend OpenAPI specification
cd backend
npm run generate-openapi

# 2. Regenerate frontend TypeScript schema definitions (lib/api/schema.ts)
cd ../frontend
npm run api:generate

# 3. Regenerate the client SDK schema (packages/client/src/schema.ts)
cd ../packages/client
npm run generate
```

#### Drift Detection in CI

To prevent API contract drift between backend route definitions and frontend API calls, CI runs:

```bash
npm run api:check-drift
```

If `backend/docs/openapi.json` has changed without updating `frontend/lib/api/schema.ts`, the check fails with an actionable error prompting regeneration.

#### Consuming Typed Clients

- **`frontend/lib/api/typedClient.ts`**: Provides type-safe `typedClient.get` and `typedClient.post` with compile-time checked path parameters, query params, request bodies, and responses.
- **`frontend/hooks/useApi.ts`**: Provides `useTypedApi` for SWR-cached, type-safe GET queries.
- **`packages/client`**: Standalone consumer package (`@stellar-marketpay/client`) for external consumers and microservices — the SDK documented above.

### Regenerate Python Client (legacy / experimental)

```bash
cd backend
npm run generate-openapi
openapi-python-client generate --path docs/openapi.json --output-path ../sdk/python
```

### Regenerate Go Client (legacy / experimental)

```bash
cd backend
npm run generate-openapi
oapi-codegen -package marketpay docs/openapi.json > ../sdk/go/client.go
```
